# 词汇声调输入与例句条数设计

## 目标

后台词汇管理中，声调使用普通文本输入和原值存储/展示；词汇列表增加“例句条数”；JSON/CSV 模板和导入流程与新的声调字符串格式保持一致。

## 表单与数据流

- 新增、编辑表单的 `pitchAccent` 状态由数组改为字符串，控件由多选框改为普通输入框。
- 声调保持必填，空值提示为“请输入声调”。
- 提交新增或编辑时，声调直接作为字符串赋给 API 的 `pitch_accent`，不调用声调 key-value 规范化逻辑。
- 编辑已有词汇时，直接读取 `pitch_accent`/`pitchAccent` 原值。为兼容历史数组数据，仅将数组连接成逗号分隔文本，不再映射选项标签或 value。
- 列表中的声调直接显示原值；历史数组值使用逗号连接后显示。

## 例句条数

- 词汇列表增加“例句条数”列。
- 计数在前端完成：数组只计算去除首尾空白后仍非空的元素；空值计为 `0`；非数组的单个非空值计为 `1`。
- 不修改列表 API 和数据库结构。

## 模板与导入

- JSON 下载模板中的 `pitchAccent` 使用普通字符串。
- CSV 模板中的 `pitchAccent` 使用普通字符串，说明文字不再描述“多个声调”或分号分隔声调。
- CSV 解析与 JSON 批量导入不对声调执行选项 key-value 映射，直接保留输入文本；API 批量写入也保持原始声调字符串。
- 类别、级别和标签继续沿用现有映射逻辑，改动仅限声调。

## 测试与验收

- 先为声调原值规范化、模板/导入和例句计数添加失败测试，再实现功能。
- 验证新增与编辑可输入任意非空声调文本，提交值与输入一致。
- 验证列表中 1 条有效例句显示 `1`，空数组或全空白例句显示 `0`。
- 验证 CSV/JSON 示例和导入后的声调均为未映射的普通字符串。
- 运行相关测试并执行生产构建。
